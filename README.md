# Recallify

Select text anywhere on the web. Save your own explanation next to it, or hide it
and practice active recall later. Your memories are stored in your browser —
there is no Recallify server or account. See [PRIVACY.md](PRIVACY.md).

## Features

- **Remember** — select text, write your own explanation, and it stays highlighted
  on the page for next time. Click the highlight to reread your note.
- **Hide & Remember** — select text, it's replaced with a `🧠 recall?` blank.
  Click it, type what you remember, and check yourself against the original.
- **Dashboard** — search and filter every memory you've saved across all sites,
  edit notes, and run a shuffled practice session over everything you've hidden.
- **Context menu** — right-click selected text as an alternative to the floating
  toolbar.
- **Sync (optional, off by default)** — turn it on in the dashboard's Appearance
  panel to sync memories through Chrome's built-in sync (your Google account).

## Tech stack

- React + TypeScript + Vite
- `@crxjs/vite-plugin` for Manifest V3 bundling (with HMR in dev)
- `chrome.storage.local` for persistence, plus `chrome.storage.sync` if you turn on
  sync — no backend, no accounts, and the extension makes no network requests of
  its own

## Project layout

```
manifest.config.ts        MV3 manifest, generated by CRXJS
src/
  background/              Service worker (context menus)
  content/                 Content script: selection toolbar, highlight &
                           hide-and-reveal engine, injected into every page
  popup/                   Toolbar popup: memories on the current page
  dashboard/               Full-page memory manager + practice mode
  lib/                     Shared types, storage, and DOM text-anchoring logic
```

### How memories survive page reloads

Each memory stores the selected text plus ~40 characters of context before and
after the selection itself (`src/lib/anchor.ts`). On reload, the content script
re-locates the same text by scanning the page's text nodes and, if the text
appears more than once, picks the occurrence whose surrounding context matches
best.

Matching ignores whitespace and letter case, so it still finds text that wraps
across source lines, spans paragraphs or inline tags, or is restyled with CSS
`text-transform`.

## Development

```bash
npm install
npm run dev     # CRXJS dev server with HMR
```

Then in Chrome:

1. Go to `chrome://extensions`
2. Enable **Developer mode**
3. Click **Load unpacked** and select the `dist` folder (first run `npm run build`,
   or point at the dev server's output per CRXJS's HMR setup)

### Checks

```bash
npm run lint        # ESLint
npm run typecheck   # tsc for the extension and the build config
npm test            # Vitest (jsdom)
```

CI runs the same checks plus a production build on every push and pull request.

## Production build

```bash
npm run build
```

Outputs a load-ready extension to `dist/`. Zip that folder's contents to submit
to the Chrome Web Store.

## Known limitations (MVP)

- Text anchoring is best-effort; heavily dynamic pages (infinite scroll,
  client-rendered content that changes after load) may not always restore
  highlights.
- Sync rides on Chrome's built-in sync, which has small quotas (about 100 KB in
  total and 8 KB per item). Very long notes, and anything beyond the quota, stay on
  the device they were saved on. Only memories sync; categories and appearance
  settings stay on each device.
- Sync is best-effort: if two devices save memories at nearly the same moment, one
  of them can go missing.
- Memories live in your browser profile, and there is no export or backup yet.
  Uninstalling the extension deletes them.
- No PDF or `file://` support in this permission set.

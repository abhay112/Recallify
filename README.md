# Recallify

Select text anywhere on the web. Save your own explanation next to it, or hide it
and practice active recall later. Everything is stored locally in your browser.

## Features

- **Remember** — select text, write your own explanation, and it stays highlighted
  on the page for next time. Click the highlight to reread your note.
- **Hide & Remember** — select text, it's replaced with a `🧠 recall?` blank.
  Click it, type what you remember, and check yourself against the original.
- **Dashboard** — search and filter every memory you've saved across all sites,
  edit notes, and run a shuffled practice session over everything you've hidden.
- **Context menu** — right-click selected text as an alternative to the floating
  toolbar.

## Tech stack

- React + TypeScript + Vite
- `@crxjs/vite-plugin` for Manifest V3 bundling (with HMR in dev)
- `chrome.storage.local` for all persistence — no backend, no accounts

## Project layout

```
manifest.config.ts        MV3 manifest, generated by CRXJS
src/
  background/              Service worker (context menus)
  content/                 Content script: selection toolbar, highlight &
                           hide-and-reveal engine, injected into every page
  popup/                   Toolbar popup: memories on the current page
  dashboard/               Full-page memory manager + practice mode
  lib/                     Shared types, storage, and DOM text-anchoring logic
```

### How memories survive page reloads

Each memory stores the selected text plus ~40 characters of context before and
after it (`src/lib/anchor.ts`). On reload, the content script re-locates the
same text by scanning the page's text nodes and, if the text appears more than
once, picks the occurrence whose surrounding context matches best.

## Development

```bash
npm install
npm run dev     # CRXJS dev server with HMR
```

Then in Chrome:

1. Go to `chrome://extensions`
2. Enable **Developer mode**
3. Click **Load unpacked** and select the `dist` folder (first run `npm run build`,
   or point at the dev server's output per CRXJS's HMR setup)

## Production build

```bash
npm run build
```

Outputs a load-ready extension to `dist/`. Zip that folder's contents to submit
to the Chrome Web Store.

## Known limitations (MVP)

- Text anchoring is best-effort; heavily dynamic pages (infinite scroll,
  client-rendered content that changes after load) may not always restore
  highlights.
- No cross-device sync yet — memories live in `chrome.storage.local` on one
  browser profile.
- No PDF or `file://` support in this permission set.
